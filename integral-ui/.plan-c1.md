# C1 — Filter / group / sort on Map

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make the Map queryable at adapter-data scale (80+ intents). Add `key:value` filter chips, group dropdown (5 options), sort dropdown (4 options), URL state, default sort `awaiting,recency`. Closes the last v0.1 stop condition.

**Architecture:** Pure utility layer (`filter-query.ts`, `intent-grouping.ts`) drives the workspace transformation; chrome layer (`FilterChip`, `FilterBar`, `GroupSortControls`, `MapControls`) renders the controls; `App.tsx` carries the URL contract. Zero new schema, zero new endpoints, zero LLM. Cleanest possible: at zero filters, the chrome looks identical to today's Map.

**Tech Stack:** TypeScript strict + zod 4 + Vitest + RTL + Playwright. No new deps.

**Design reference:** `integral-ui/.notes-v0.1.5.md` themes captured the data-density problems C1 solves; the recommendation thread above this file's commit captures the chosen design (filter-as-tokens, typographic group separators, compound default sort, URL contract). This plan is the implementation of that design.

## Goal

A user opening Integral with all 3 adapters loaded can:

1. **Default state (zero filters):** see the Map exactly as today's chrome — flat 2-col grid of TreeCards. No new visual chrome paid for at this state.
2. **Click `+ filter`** → autocomplete overlay grouped by category (status, kind, holder, tag) → click `awaiting:me` → chip appears in the row, Map narrows.
3. **Click `+` again** → add another chip (`kind:nous-campaign`). Multi-select within a category is OR; across categories is AND.
4. **Group/sort dropdowns appear** when ≥1 filter is active. Choose `group: source`. Map renders typographic section separators per source.
5. **Reload page** — filters persist via URL state (`?awaiting=me&kind=nous-campaign&group=source`). Share the URL — same view.
6. **Filter to empty** — see `0 intents match … · clear filter →` in the same typographic genre.
7. **Click `×` on a chip** → it's removed; Map widens.

**Stop conditions:**

- Zero-filter visual baseline is **unchanged** (regression test against existing baselines passes without regen).
- Filter chips render as `key:value` mono tokens; remove `×` works.
- Group rendering uses typographic separators (small uppercase label + count + horizontal rule), not heavy section bars.
- Sort default is compound `awaiting,recency` (awaiting-me items rise; otherwise newest first).
- URL state round-trips: `parseFilterQuery(serializeFilterQuery(filters)) === filters` for any filter set.
- Filter+group+sort all apply across all 3 adapter sources (Nous + Coral + GitHub-issues).
- Verification quintuple green: `test:run` + `typecheck` + `build` + `test:e2e` + `test:e2e:visual`.
- `roadmap.md` flips C1 to ✓ done; `CLAUDE.md` "Current state" updated; test counts bumped.
- v0.1 stop conditions all met (this is the last one).

**Out of scope (deferred to v0.1.5 or v0.2):**

- Cmd+K command palette (v0.1.5 enhancement on top of the chip system).
- Saved views / view tabs (v0.2 if at all — URL-shareability covers 80% of the use case).
- Free-text search across titles (v0.1.5 separate concern).
- Drag-to-reorder cards (Map is read-only orientation, never).
- Density toggle (small/medium/large cards) — adds chrome without solving real problem.
- Hierarchy depth control (expand/collapse all for tracking issues) — v0.2 with orchestrator's parent-child story.
- Filter on `awaiting_party` (other than self) or `provenance.declared_by` — could land in v0.1.5; not v0.1.

### Filter shape (the typed core)

```ts
// src/lib/filter-query.ts
export interface FilterQuery {
  /** awaiting:me means restrict to intents where isAwaitingMe(...) is true. */
  awaitingMe?: boolean
  /** Multi-select within category = OR. */
  kinds: ReadonlySet<IntentKind>
  statuses: ReadonlySet<Status>
  holderModes: ReadonlySet<HolderMode>
  /** Free-form tag values; OR across multiple. */
  tags: ReadonlySet<string>
}

export type GroupBy = 'none' | 'source' | 'kind' | 'holder-mode' | 'status'
export type SortBy = 'awaiting-recency' | 'recency' | 'status' | 'alphabetical'

export interface MapView {
  filter: FilterQuery
  group: GroupBy
  sort: SortBy
}
```

Defaults: `filter = { awaitingMe: false, kinds: ∅, statuses: ∅, holderModes: ∅, tags: ∅ }`, `group: 'none'`, `sort: 'awaiting-recency'`.

### URL contract

```
/?sources=fixture,nous,coral-pi-mc&awaiting=me&kind=nous-campaign,coral-attempt&status=active&group=source&sort=recency
```

Multi-value params comma-separated (matches existing `?sources=`). Default values omitted from URL (`group=none&sort=awaiting-recency` are the no-ops). `serializeFilterQuery` emits the URL; `parseFilterQuery` accepts it.

### Group rendering

Sections are separated by **typographic dividers**, not heavy section bars:

```
NOUS / INFERENCE-SIM ─── 30 ────────────────────────────────────────
[card] [card]
[card] [card]
…

CORAL / PI-MC ─── 1 ────────────────────────────────────────────────
[card]
```

Subtle horizontal rule, mono uppercase label, count chip — all reusing existing tokens (`var(--ink-3)` for the rule, `Plex Mono` for the label, the existing `Chip mono soft` for the count).

### Default sort: `awaiting-recency`

Compound. `awaiting:me === true` items first, sorted by `last_advanced_at desc`; rest of intents next, sorted by `last_advanced_at desc`. Implemented as: `intents.sort((a, b) => awaitingScore(b) - awaitingScore(a) || dateDesc(b, a))`.

`awaitingScore` is `1` if `isAwaitingMe(intent, state, me)` else `0`. Reuses the existing predicate from `src/lib/queue.ts`.

## Mapping — categories → values

### Filter categories (the `+ filter` overlay groups)

| Category | Values | Type |
|---|---|---|
| **STATUS** | active · gated · satisfied · abandoned · revoked · draft | enum (multi-select OR) |
| **KIND** | nous-campaign · nous-iteration · coral-optimization · coral-attempt · feature-campaign · feature-pr · paper-campaign · paper-section · paper-claim | enum (multi-select OR) |
| **HOLDER** | awaiting:me · holder:human · holder:agent · holder:hierarchical | mixed (awaiting:me is special; others are HolderMode) |
| **TAG** | (autocomplete from `intent.tags` across all loaded intents) | string set |

Intra-category = OR (`kind=nous-campaign,coral-attempt` matches either). Cross-category = AND (`status=active kind=nous-campaign` matches active Nous campaigns only).

### Group options

| Value | Group key derivation | Display label |
|---|---|---|
| `none` (default) | n/a | (no separators) |
| `source` | `intent.provenance.source ?? 'fixture'` | sourceId, uppercased |
| `kind` | `intent.kind` | IntentKind, uppercased |
| `holder-mode` | `intent.holder.mode` | HolderMode, uppercased |
| `status` | `state.status` | Status, uppercased |

`tag` is NOT a group option (open-ended set; would generate too many groups).
`awaiting` is NOT a group option (the sort handles it).

### Sort options

| Value | Comparator |
|---|---|
| `awaiting-recency` (default) | awaiting first, then `last_advanced_at desc` |
| `recency` | pure `last_advanced_at desc` |
| `status` | severity order: gated < active < satisfied < abandoned < revoked < draft |
| `alphabetical` | `declaration.title` asc, locale-aware |

## Visual + interaction details (the design specifics)

### `+ filter` disclosure

Native `<details>` element with `<summary>` showing `+ filter`. Open state reveals categories:

```
<details class={styles.filterDisclosure}>
  <summary>+ filter</summary>
  <div class={styles.categories}>
    <section>
      <h4>STATUS</h4>
      <button onClick={() => onAdd('status:active')}>active</button>
      <button onClick={() => onAdd('status:gated')}>gated</button>
      …
    </section>
    <section>
      <h4>KIND</h4>
      …
    </section>
    …
  </div>
</details>
```

Why `<details>`: native disclosure, accessible, keyboard-supported, no framework chrome, matches the cognitive-instrument genre's preference for web-platform primitives.

### Sort + group dropdowns

Same `<details>` pattern:

```
<details>
  <summary>group: <span>none</span></summary>
  <ul role="menu">
    <li><button onClick={() => onChange('none')}>none</button></li>
    <li><button onClick={() => onChange('source')}>source</button></li>
    …
  </ul>
</details>
```

Click outside closes (handled via document click listener cleanup).

### Group separator styling

```css
.groupSeparator {
  display: flex;
  align-items: center;
  gap: var(--space-2);
  font-family: 'IBM Plex Mono', monospace;
  font-size: 11px;
  text-transform: uppercase;
  color: var(--ink-2);
  letter-spacing: 0.04em;
  margin: var(--space-6) 0 var(--space-3);
}

  content: '';
  flex: 1;

```

Result: `NOUS / INFERENCE-SIM ─── 30 ────────────────────────────────`. The `30` is a `<Chip mono soft>` element. The `─` is a CSS pseudo-element with `flex: 1`.

### Filter chip styling

Reuses `<Chip mono>` for the typography. Adds a small × button next to it. The chip body is the literal text `kind:nous-campaign` (no styling on the colon — let the colon read naturally). On `:hover`, the × goes amber.

### Empty-state styling

```
<div class={styles.empty}>
  <p>0 intents match awaiting:me kind:paper-claim</p>
  <button class={styles.clearLink} onClick={onClearAll}>clear filter →</button>
</div>
```

Centered horizontally in the Map column. `var(--ink-2)` muted text. The `clear filter →` is hyperlink-styled (underline on hover, amber accent on focus).

### Mobile/narrow (<768px)

Collapse FilterBar + GroupSortControls into a single sheet trigger:

```

```

Tap either → opens a full-width `<details>` that reveals the controls vertically. Source picker keeps its own row.

## Edge cases & escape valves

- **Filter that excludes nothing.** A user adds `kind:nous-campaign` but only nous campaigns are loaded. Map looks identical to unfiltered. The chip is still visible in the bar — that's correct (the user expressed intent; the chrome doesn't second-guess).
- **All-source filter excludes everything from one source.** E.g., `kind:paper-claim` → only fixture has paper-claim intents. The user with `?sources=nous,coral` sees zero results. Empty state with clear-filter link.
- **URL has both `awaiting=me` and `holder:agent`.** AND across categories — only intents that are awaiting-me AND held by an agent. Possible but unusual; honor what the URL says.
- **Tag with a comma in it.** Defensive: tags shouldn't contain commas. If they do (gap recorded), URL-encode before splitting. `,%2C,` round-trip-safe.
- **Status filter with `draft`.** Currently no draft intents flow through adapters. Filter has no effect. UI shows the chip honestly; v0.2 might surface drafts.
- **Sort by `status` ties.** Within same status, fall back to recency desc (compound).
- **Group by `tag` (not exposed but considered).** Single intent can have multiple tags; would create overlap. Explicitly NOT a group option per design.
- **Auto-show GroupSortControls when filter active.** Edge case: user removes the last filter → controls disappear. Reasonable; the user can re-trigger by adding another filter. If we get user feedback that this is jarring, add a "stick" mode in v0.1.5.
