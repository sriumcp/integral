## Per-adapter primary outcome + cleanup

Three adapters, three different outcomes, three different cleanups. The discipline: cut affordances that don't serve the primary outcome, add the ones that do.

### Nous — the shaper goes from transcription to enablement

**User outcome:** move a research question through an iterative cycle: shape → run → read → iterate.

**Status:** the shape end works (A4.6 chat shaper). The read-and-iterate handoff is weak. Today the shaper is responsive — user says X, LLM transcribes X. To be enabling:

1. **Show the resulting `campaign-X.yaml` in real time** as fields fill. User verifies before committing instead of "trust me."
2. **Pre-flight validation during shaping.** Does `target_system.repo_path` exist? Is `nous` installed? Inline hints, not modals.
3. **Socratic prompts on the research question.** Push back: "this is descriptive, not predictive — what would you bet on?" Karpathy-genre = small inline hint.
4. **Templates from past campaigns.** "You shaped a similar campaign 3 weeks ago — start from `best-of-field-comparison`?"
5. **Aftermath integration.** When a campaign completes, offer: "want to shape a follow-up that builds on iter-2's confirmed h_main?"
6. **Visible commit audit** — show what's about to be written, where, and what command will run.
7. **Concerns inline, not paneled** — move the LLM's concerns next to the fields they're about.

### Coral — read-comprehension that lets the user steer

**User outcome:** steer a population-based optimization — what's the leader, what's gaming, what's the trend, what should I try next.

**Status:** read-only in v0.1; v0.2 brings shaping + orchestration. v0.1.5's job is to make the read affordances actually serve the steering outcome.

1. **Best-so-far chart** across attempts. The single most useful Coral artifact is the leader trend; currently no visualization.
2. **Gaming-detection signal.** The `math.pi` attempt hit the 1e12 cap — that's a structural tell. Mark suspicious attempts visibly.
3. **Side-by-side attempt diff** in `solution.py`. Coral is fundamentally about variation; the chrome should make variation legible.
4. **Agent personalities visible.** `roles/agent-N.md` is rich today (G-C-4 lossy); surface the persona inline on attempt cards.
5. **Notes-as-principles, in context.** G-C-10 lossy today; surface note bodies / excerpts on campaign Detail.

### GitHub-issues — make the queue actually triagable

**User outcome:** triage work in a repo — what needs me, what's blocked, what's in flight, what's connected.

**Status:** read-only in v0.1; issue creation / commenting from chrome is v0.2 writeback. v0.1.5's job is to make the triage outcome work.

1. **Timeline events + comments loaded.** Promotes G-F-7 + G-F-8 from candidate to commitment. Activity Strip on GitHub Detail is silent today; making it speak is the highest-leverage fix.
2. **Linked PRs as references.** `linked_pull_requests` field exists on issues; surface as a chip on Detail ("linked: PR#123 ci-failing") — typed as `EvidenceLink`, not yet `feature-pr` Intent.
3. **Stale-data signal honest.** "Synced 12m ago · refresh →" when external state may have drifted.
4. **Markdown body rendering** on Detail. Issues use markdown — render them.
5. **Body-search / jump-to-issue** via `/` keyboard shortcut.
6. **One-click jump to github.com to comment** until v0.2 brings issue writeback.

### Pattern: read-comprehension cleanup vs. shaper cleanup

| Adapter | Read-comprehension cleanup | Shaper cleanup |
|---|---|---|
| Nous | Aftermath integration; principle visibility | Items 1-7 above |
| Coral | Items 1-5 above | Deferred to v0.2 (writeback / orchestrator) |
| GitHub | Items 1-5 above | "Jump to github.com" affordance; full creation v0.2 |

Nous gets shaper improvements because the shaper *exists* and is the user's entry point. Coral and GitHub-issues are read-only in v0.1 — v0.1.5's outcome work for them is about making *reading* serve their respective outcomes.

## Falsification per adapter (the v0.1.5 stop conditions)

Each cleanup needs a checkable anchor — analogous to B1/B2's "schema accepts this without modification."

- **Nous:** committing a campaign whose `target_system.repo_path` doesn't exist on disk is gated by the pre-flight check. The user sees the validation failure inline, not after running.
- **Coral:** the `math.pi` spec-gaming attempt is visually marked "score = grader cap; verify" on the campaign Detail.
- **GitHub-issues:** the Activity Strip on a real GitHub issue Detail shows ≥1 timeline event when the issue has any comments. (No more "no activity yet" for active issues.)

These three anchors prove the chrome serves the outcome — not "looks polished," not "renders correctly," but "the user can do their job."
